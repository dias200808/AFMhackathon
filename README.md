# КӨЗ (KÓZ) · AI Media Watch

ИИ-консоль аналитика **АФМ** для выявления признаков **незаконного игорного бизнеса и финансовых пирамид** в соцсетях.

## Старый vs новый датасет (ML-эксперимент)

Вкладка **«Старый vs новый»** в консоли показывает, что даёт расширение данных. Модель одна и та же
(TF-IDF слов и символов + ручные признаки → LogisticRegression), меняется **только обучающий датасет**.
Обе модели проверяются на одном отложенном наборе из 106 реалистичных постов (`data/eval_holdout.jsonl`),
совпадения с которым автоматически исключаются из обучения.

| | Исходный датасет (v00) | Расширенный датасет (v09) |
|---|---|---|
| Строк | 520 | 1952 |
| Accuracy (отложенный набор) | 54.7% | **93.4%** |
| Macro-F1 | 63.9% | **94.7%** |
| Пойманные угрозы | 40.8% | **95.8%** |
| Без ложной тревоги | 88.6% | **100%** |

Расширение: трудные негативы, казахский язык, казахстанская специфика (Kaspi/Halyk, тенге), обфускация,
новые схемы мошенничества (HYIP/MLM, pump-and-dump, фейковые «советники»). Внутренний F1 исходного датасета
0.997 при реальном 0.64: модель запоминала шаблоны.

## Поиск по графу: сети мошенников

Во вкладке **«Граф»** посты и их сущности (ссылки, Telegram-каналы, кошельки, промокоды, бренды) образуют граф.
Два алгоритма поиска (`app/graph/search.py`) работают поверх него, с пояснением и анимацией обхода прямо в интерфейсе:

- **BFS (поиск в ширину)**: от одного поста или ссылки обходит граф слоями и собирает всю связанную сеть.
  Пример на реальных данных: одна ссылка → 12 постов → ещё 5 ссылок на тот же сайт.
- **Uniform-cost search**: самая «дешёвая», то есть самая доказательная, цепочка между двумя объектами.
  Стоимость связи зависит от силы улики: ссылка, Telegram, кошелёк, телефон = 1; уникальный промокод = 2;
  бренд казино и общие слова вроде «Promo Code» или «2025» = 4 (по умолчанию не учитываются).

API: `GET /api/graph/network`, `GET /api/graph/path`, `GET /api/graph/search-examples`.

> «КӨЗ» (каз. *глаз*) — непрерывно собирает посты соцсетей, оценивает риск **собственной обученной моделью**, объясняет признаки нарушения на русском и выстраивает **приоритетную очередь** «что проверять первым».

## Что внутри (по критериям оценки)

1. **Актуальность + обоснование AI** — мониторинг соцсетей вручную невозможен по объёму; AI обязателен.
2. **Своя модель, независимая от сервисов** — риск-классификатор `TF-IDF (word + char_wb) + ручные сигналы → LogisticRegression` (только scikit-learn, **без torch и без внешних API**). Обучается локально за секунды. Метрики: **macro-F1 ≈ 0.94** (реалистичная confusion matrix), экран `/api/metrics`.
3. **ИБ + этика** — только публичные данные; **human-in-the-loop** (система *приоритизирует для проверки*, не блокирует автоматически); объяснимость каждого флага; SSRF-защита в live-проверке.
4. **Реализуемость + масштаб** — модульный пайплайн, авто-роутеры, путь MVP (SQLite) → прод (Postgres + очередь).
5. **Презентация + тех-защита** — светлая аналитическая консоль: лента/очередь, drill-down с доказательствами по модальностям, граф связей, тренды, PDF-досье, живая проверка.

## Запуск (Windows, одна команда)

```bat
setup.bat   :: создаёт .venv и ставит зависимости (один раз)
run.bat     :: поднимает сервер на http://127.0.0.1:8000
```

Вручную (любая ОС, Python 3.11+):

```bash
python -m pip install -r requirements.txt
python -m scripts.gen_dataset      # сгенерировать датасет RU+KZ (опц. — уже в репо)
python -m app.model.train          # обучить модель -> app/model/artifacts/ (опц. — уже в репо)
python -m scripts.build_demo       # собрать демо-ленту (опц. — уже в репо)
python -m uvicorn app.main:app --port 8000
```

Открыть **http://127.0.0.1:8000** — лента наполняется автоматически (фоновый «дрип» seed-постов).

## Реальный сбор и тяжёлые экстракторы (продукт-режим)

Помимо seed-демо, КӨЗ работает на **живых данных**:

- **Сканер Telegram** (вкладка «Лента») — вводишь публичный канал → система **реально выгружает** его посты (web-preview `t.me/s/`, без авторизации), извлекает сущности и скорит своей моделью; они попадают в ленту/граф/тренды.
- **Watchlist** (вкладка «Мониторинг») — список каналов сканируется **периодически в фоне** (непрерывный мониторинг).
- **Разбор по ссылке/файлу** (вкладка «Живая проверка») — ссылка TikTok/YouTube/Instagram/Telegram **или загруженный файл** → **реальное скачивание (yt-dlp)** + **настоящий мультимодал**: Whisper (аудио→текст), EasyOCR (текст с кадров), open-CLIP (визуальные маркеры) → скор своей моделью. Тяжёлый разбор идёт в **фоновой очереди** с прогрессом (`/api/jobs/{id}`), не блокируя UI; ошибки деградируют мягко (без 500).

Тяжёлые экстракторы **опциональны** (ядро/демо работают на тексте и закэшированных признаках без них). Установка:

```bash
pip install -r requirements-extractors.txt
# torch — CPU-сборкой:  pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
# + статичный ffmpeg+ffprobe (нужен yt-dlp для нарезки/склейки):
#   https://github.com/BtbN/FFmpeg-Builds/releases -> ~/AppData/Local/Programs/ffmpeg/bin (или env KOZ_FFMPEG_DIR)
```

**Честно о площадках:** Telegram (публичные каналы) и загрузка файла — надёжны. TikTok/Instagram активно защищаются от ботов и могут временно блокировать скачивание по IP (rate-limit); тогда live-разбор по ссылке деградирует мягко, а надёжный путь — **загрузка файла**. Массовый скрейпинг целых лент не обещаем — только по ссылке/каналу.

## Архитектура

```
ingestion (seed-дрип + live yt-dlp/upload)
  → extractors (текст/сущности; ленивые Whisper/OCR/CLIP с кэшем)
  → СВОЯ МОДЕЛЬ (риск 0–100 + категория + объяснение)
  → decision (скоринг/рекомендация/аудит)
  → консоль (лента · граф · тренды · PDF · живая проверка)
```

- Бэкенд: **FastAPI + SQLite**. Своя модель: **scikit-learn**. PDF: **reportlab**.
- Роуты подключаются авто-роутером из `app/**/routes.py` (фичи не правят `main.py`).
- Документы защиты: `docs/pitch/` — питч, демо-скрипт, Q&A и **слайд-дек `docs/pitch/deck.html`** (открыть в браузере, листать стрелками; самодостаточный, офлайн). Дизайн/план: `docs/superpowers/`.

## Этика и ограничения

Система выдаёт **риск-сигнал для аналитика**, а не приговор. Все флаги объяснимы. Используются только публичные данные; персональные данные не профилируются. Окончательное решение — за человеком.
